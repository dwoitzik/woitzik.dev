Tailscale solves the "access everything from anywhere" problem better than any VPN I've used, and the client experience is excellent. My problem with it is the control plane: your device list, user identities, and ACL policies all live on Tailscale's servers. I wanted that state on my own hardware. My k3s cluster runs on a [BMAX Mini PC\*](/go/4bv3yF1), the same box that handles everything from ArgoCD to local LLM inference.

[Headscale](https://github.com/juanfont/headscale) is a self-hosted, open-source implementation of the Tailscale control plane. Same WireGuard mesh, same clients, but your data stays on your infrastructure. If you already run k3s with ArgoCD, adding Headscale takes one more Application.

> **Update (November 2026):** Longhorn is gone from this cluster. Headscale's PVC now uses `local-path` storage, and its SQLite database is replicated with Litestream to a warm standby on a separate host. The Longhorn steps below show the original setup; swap the `storageClassName` for whatever your cluster uses.

**[View the complete homelab infrastructure source on GitHub](https://github.com/dwoitzik/homelab-infrastructure)**

## The Architecture

```
Tailscale Client (any device)
        │
        ▼
Traefik IngressRoute (headscale.yourdomain.com)
        │
        ▼
Headscale Service (port 8080)
        │
        ├── Auth: Authelia OIDC (auth.yourdomain.com)
        ├── State: SQLite on Longhorn PVC
        └── DERP: Tailscale's relay servers (external)
```

Headscale handles device registration and key exchange. Actual traffic flows peer-to-peer over WireGuard (or through a DERP relay when no direct path exists). The control plane is not in the data path.

## Step 1: Persistent Storage with Longhorn

Headscale stores its private keys and SQLite database on disk. A pod restart must not lose them, because they are the root of trust for your entire WireGuard mesh.

```yaml
# kubernetes/apps/headscale/pvc.yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: headscale-data
  namespace: apps
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: longhorn
  resources:
    requests:
      storage: 5Gi
```

`ReadWriteOnce` is correct here because Headscale runs as a single replica.

## Step 2: Headscale Configuration

The full configuration lives in a ConfigMap. The key names below are for Headscale 0.22.x, the version this deployment pins. Headscale 0.23 renamed several of them (`database.type`, `dns`, `policy.path`, among others), so check the `config-example.yaml` for your release before copying.

```yaml
# kubernetes/apps/headscale/configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: headscale-config
  namespace: apps
data:
  config.yaml: |
    server_url: https://headscale.yourdomain.com
    listen_addr: 0.0.0.0:8080
    metrics_listen_addr: 0.0.0.0:9090  # default is 127.0.0.1:9090, unreachable from outside the pod

    private_key_path: /var/lib/headscale/private.key
    noise:
      private_key_path: /var/lib/headscale/noise_private.key

    db_type: sqlite3
    db_path: /var/lib/headscale/db.sqlite

    derp:
      server:
        enabled: false
      urls:
        - https://controlplane.tailscale.com/derpmap/default
      auto_update_enabled: true
      update_frequency: 24h

    dns_config:
      magic_dns: true
      base_domain: headscale.net
      nameservers:
        - 10.0.20.5       # your internal DNS resolver
      extra_records: []

    oidc:
      issuer: "https://auth.yourdomain.com"
      client_id: "headscale"
      client_secret: "<your-oidc-client-secret>"
      scope: ["openid", "profile", "email"]
      strip_email_domain: true

    ip_prefixes:
      - 100.64.0.0/10     # Tailscale CGNAT range

    acl_policy_path: /var/lib/headscale/policy.hujson
```

**`metrics_listen_addr`** has to be set explicitly. Headscale binds its metrics endpoint to `127.0.0.1:9090` by default, so declaring `containerPort: 9090` in the Deployment alone gives Prometheus nothing to scrape.

**DERP relays** are left to Tailscale's infrastructure (`controlplane.tailscale.com/derpmap/default`). Running your own DERP server adds operational overhead for little benefit in a homelab.

**OIDC** delegates authentication to [Authelia](/blog/k3s-authelia-proxmox-homelab/). When a new device registers, the user signs in through the Authelia web UI, so there is no separate Headscale user management.

**`ip_prefixes: 100.64.0.0/10`** is the standard Tailscale CGNAT range. Clients in your mesh will receive addresses from this space.

## Step 3: The Deployment

```yaml
# kubernetes/apps/headscale/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: headscale
  namespace: apps
spec:
  replicas: 1
  strategy:
    type: Recreate        # never two instances with the same SQLite file
  selector:
    matchLabels:
      app: headscale
  template:
    metadata:
      labels:
        app: headscale
    spec:
      containers:
        - name: headscale
          image: ghcr.io/juanfont/headscale:0.22.3
          args:
            - headscale
            - serve
          ports:
            - name: http
              containerPort: 8080
            - name: metrics
              containerPort: 9090
          volumeMounts:
            - name: config
              mountPath: /etc/headscale/config.yaml
              subPath: config.yaml
              readOnly: true
            - name: data
              mountPath: /var/lib/headscale
      volumes:
        - name: config
          configMap:
            name: headscale-config
        - name: data
          persistentVolumeClaim:
            claimName: headscale-data
```

`strategy: Recreate` matters. With SQLite, two pods writing at the same time can corrupt the database. Recreate stops the old pod before starting the new one instead of doing a rolling update.

## Step 4: Service and IngressRoute

```yaml
# kubernetes/apps/headscale/service.yaml
apiVersion: v1
kind: Service
metadata:
  name: headscale
  namespace: apps
spec:
  ports:
    - port: 8080
      targetPort: 8080
      name: http
  selector:
    app: headscale
---
# kubernetes/apps/headscale/ingress.yaml
apiVersion: traefik.io/v1alpha1
kind: IngressRoute
metadata:
  name: headscale
  namespace: apps
spec:
  entryPoints: [websecure]
  routes:
    - match: Host(`headscale.yourdomain.com`)
      kind: Rule
      services:
        - name: headscale
          port: 8080
  tls:
    secretName: wildcard-yourdomain-tls
```

Headscale does not need an Authelia middleware on the IngressRoute, because it handles authentication itself through the OIDC flow. A forward-auth middleware would also break the Tailscale clients, which talk to this endpoint directly. Headscale ships no web UI; if you add a third-party one, put that behind Authelia.

## Step 5: Authelia OIDC Client

In your Authelia configuration, add the Headscale client:

```yaml
identity_providers:
  oidc:
    clients:
      - client_id: headscale
        client_name: Headscale
        client_secret: "<bcrypt-hash-of-your-secret>"
        public: false
        authorization_policy: one_factor
        redirect_uris:
          - https://headscale.yourdomain.com/oidc/callback
        scopes:
          - openid
          - profile
          - email
```

The `client_secret` in Authelia is a hash (bcrypt here) of the plaintext secret in the Headscale config. Authelia stores only the hash and checks the plaintext secret Headscale sends when it exchanges the authorization code at the token endpoint.

## Registering a Client

Once Headscale is running, register clients using the standard Tailscale client with a custom login server:

```bash
# Linux / macOS
tailscale up --login-server https://headscale.yourdomain.com

# On a machine where tailscale is already running
tailscale login --login-server https://headscale.yourdomain.com
```

The client prints (or opens) a login URL on your Headscale server, which redirects to Authelia. After you authenticate, Headscale registers the device and assigns it an address from `100.64.0.0/10`.

## Access Control Policy

Headscale loads a HuJSON ACL policy from `acl_policy_path` (in 0.23+ the key is `policy.path`). A minimal policy that lets all nodes talk to each other:

```json
{
  "acls": [
    {
      "action": "accept",
      "src": ["*"],
      "dst": ["*:*"]
    }
  ]
}
```

For tighter control, restrict access by user or tag with the same policy syntax as Tailscale's ACLs.

## The Result

- Every device enrolled in Headscale can reach every other device over WireGuard, through NAT and firewalls (relayed via DERP when a direct path fails)
- Authentication goes through Authelia, with no separate Headscale user accounts
- The database and keys are on Longhorn, [backed up daily by Velero](/blog/velero-garage-k3s-backup/)
- The entire deployment is a `git push` away from any machine

---

A self-hosted control plane is one more service to operate, and it is worth it if you care where your device and identity data lives. The WireGuard mesh gives you a flat private network across all your devices, so you can reach homelab services from anywhere without exposing them to the public internet. The Headscale endpoint itself is the one thing that has to be public.

In Azure, the same zero-trust access problem gets solved with Private Link and Managed Identity instead of WireGuard.
