Prometheus + node-exporter + Grafana works well, but it's heavy for what I needed: CPU, memory, disk, and network per host. On a 4-node k3s cluster with 2GB RAM per node, the monitoring stack itself consumed 400MB. Beszel does the same job with 30MB — a lightweight hub-agent architecture that runs anywhere.

The deploy almost failed before any pod was created. Kyverno's `disallow-latest-tag` policy rejected the image. That's exactly the point.

## Why Beszel

I needed host-level metrics — not application metrics, not custom dashboards, just "is this node healthy?" Prometheus + node-exporter + Grafana gives you that, but it also gives you:
- 200MB+ memory footprint for the operator
- Alertmanager configuration
- Prometheus retention and storage tuning
- Grafana dashboard management

Beszel gives you:
- Single binary, ~30MB memory
- Hub + agent architecture
- Built-in dashboards
- Docker and Kubernetes support
- Historical data without retention config

For host-level monitoring on a small homelab, it's the right tool.

## The Deploy

```yaml
# kubernetes/apps/beszel/beszel.yml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: beszel-data
  namespace: apps
spec:
  accessModes: [ReadWriteOnce]
  storageClassName: nfs-client
  resources:
    requests:
      storage: 1Gi
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: beszel
  namespace: apps
spec:
  replicas: 1
  selector:
    matchLabels:
      app: beszel
  template:
    metadata:
      labels:
        app: beszel
    spec:
      containers:
        - name: beszel
          image: henrygd/beszel:0.9.1
          ports:
            - containerPort: 8090
          volumeMounts:
            - name: data
              mountPath: /beszel_data
          resources:
            requests:
              memory: 30Mi
              cpu: 10m
      volumes:
        - name: data
          persistentVolumeClaim:
            claimName: beszel-data
```

## Kyverno Caught the :latest Tag

The first deploy used `henrygd/beszel:latest`. Kyverno's `disallow-latest-tag` ClusterPolicy rejected it before any pod was created:

```
Error: admission webhook "disallow-latest-tag.kyverno.svc" denied the request:
Resource beszel/beszel has container 'beszel' with image tag 'latest'
```

ArgoCD's sync just retried and failed cleanly. No silent failure, no partial deployment — the policy blocked it at admission. Pinned to `0.9.1` and the deploy succeeded.

This is exactly the point of policy-as-code. The first deploy attempt would have worked without Kyverno — `:latest` is valid, the image exists, Kubernetes pulls it. But it's a ticking time bomb: the next deploy might pull a breaking change, and you'd have no idea which commit introduced it.

## The Agent

The hub runs in-cluster. The agent runs on the host via Docker:

```bash
# On each node you want to monitor
docker run -d \
  --name beszel-agent \
  --restart unless-stopped \
  --network host \
  --volume /var/run/docker.sock:/var/run/docker.sock:ro \
  -e BESZEL_HUB_URL=https://beszel.woitzik.dev \
  -e BESZEL_HUB_KEY=<public-key-from-hub> \
  henrygd/beszel-agent:0.9.1
```

The `BESZEL_HUB_KEY` is the hub's public key — not a secret. Same sensitivity as any plain config value. The agent pushes data to the hub; no inbound connections needed.

## What It Monitors

- CPU usage and load average
- Memory usage and swap
- Disk usage and I/O
- Network traffic
- Docker container stats (if Docker socket is mounted)
- System temperature

All without Prometheus, without node-exporter, without Grafana configuration. The hub has built-in dashboards.

## The Tradeoff

Beszel doesn't replace Prometheus for application-level metrics. If you need custom dashboards, alerting rules, or service-level metrics, stay with Prometheus. Beszel is for "is this host healthy?" — the ops-level view that doesn't need PromQL.

For a small homelab with 4 nodes, it's the right level of monitoring. The 400MB I freed up from the Prometheus stack went to actual workloads.
